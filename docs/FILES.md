# 파일 서비스

## 현재 제공 범위

서버 간 파일 연동의 첫 단위다. 업로드 세션 생성, 최대 5,000,000,000바이트 파일의 분할·재개, SHA-256 검증, 목록·정보·다운로드·삭제와 공개 범위 변경을 제공한다. 프로젝트·환경은 API 키에서 결정하며 요청자가 임의로 지정하지 않는다.

관리자 파일 메뉴에서 업로드·재개와 파일 목록, 상세·보기, 용도별 URL, 공개 범위·삭제·보존 코드·자동 정리를 제공한다. 이미지·영상 썸네일과 지원 영상/오디오/PDF/TXT/MD 미리보기, HLS 화질 변환을 비동기 처리한다. 이용자 JWT/위임 업로드, 비밀번호 공유·OG, 동일 내용 중복 안내는 **후속 구현**이며 첫 출시 범위에서 제외하지 않는다.

## 관리자 파일 화면

왼쪽 **파일** 메뉴에서 프로젝트·조회 환경을 선택한다. **파일 목록 / 업로드·재개 / 보존 정책** 탭으로 작업을 나누고 다른 메뉴와 선택 범위를 공유한다. 업로드는 한 번에 20개까지 대기하고 하나씩 전송한다. 새 파일의 공개 범위와 보존 코드는 추가 전에 선택하며 기본은 공개·`default`다.

저장 파일의 **상세·보기**에서 썸네일, 문서·영상·오디오, 원본을 확인하고 기본 뷰어·원본·미리보기·썸네일·다운로드 URL을 복사하거나 새 창으로 연다. 준비 중·미지원·실패를 업로드 실패와 구분한다. 실패한 생성 작업은 다시 시도할 수 있다. 영상은 변환 전 지원 원본 부분 재생, 변환 후 **자동·360p·720p·1080p HLS**를 제공한다. 실제 생성한 화질만 표시하고 HLS URL도 복사한다.

원본 확인은 Web Worker의 `hash-wasm` SHA-256으로 4MiB씩 읽고 조각 검증은 최대 8MiB씩 수행한다. 파일 전체를 메모리에 올리지 않는다. 전송 중에는 프로젝트·환경 이동을 막고, 일시정지하면 이동할 수 있다. 새로고침·다른 화면 방문 후에는 같은 관리자 소유의 미완료 세션을 조회하고 같은 원본을 재선택한다. 크기와 전체 해시가 다르면 전송하지 않는다. 세션 생성 전 원본 확인 중이던 파일은 다시 추가해야 한다. 생성 응답이 유실되어도 요청 ID로 로컬 항목과 서버 세션을 합쳐 중복 표시하지 않는다. 네트워크 오류의 조각 재시도는 최대 2회이며 서버 확정 위치를 다시 읽는다. 연결 복구 후 사용자가 재시도할 수 있다.

관리 API는 `/api/v1/files/admin/environments/{environmentId}` 아래에 있으며 해당 플랫폼 관리자 realm의 서명·발급자·대상(`platform-admin-api`)·`platform-admin` 역할을 검증한다. 관리자 토큰을 사용하고 서버 API 키를 브라우저에 전달하지 않는다. 세션 소유권은 관리자/서버 키 종류와 식별자를 함께 확인한다. 완료 파일은 같은 환경의 관리자가 관리할 수 있다. 매 요청 프로젝트·환경의 사용 가능 상태를 내부 API로 확인한다.

다운로드 버튼은 관리자 인증 후 최대 60초의 일회용 링크를 발급한다. 유효 기간은 관리자 토큰 만료를 넘지 않으며 DB에는 무작위 비밀값의 SHA-256만 보관한다. 링크를 가진 사람은 1회 다운로드할 수 있으므로 공유하지 않는다. 같은 파일에 새 링크를 발급하면 이전 미사용 링크를 무효화한다. 공개 범위 변경·삭제도 미사용 링크를 폐기한다. HEAD 요청은 소비 없이 거부하고, GET은 원자적으로 소비한 뒤 현재 파일·환경 상태를 재검사한다. 실패했다면 새로 다운로드를 요청한다. 이미 시작된 전송은 회수하지 않는다. 브라우저 기본 다운로드를 사용하므로 전체 파일을 Blob으로 복사하지 않는다.

파일 명세는 **33개 경로/39개 작업**이다. 관리자용 업로드 목록은 자기 세션만 반환한다. 이용자 realm의 JWT를 관리자 API 권한으로 인정하지 않는다.

## 인증과 접근 범위

| 권한 | 허용 동작 |
|---|---|
| `files:read` | 같은 환경의 파일 목록·정보·보존 코드, 비공개 콘텐츠와 보기 링크 발급, 파일 API 명세 |
| `files:write` | 업로드 생성·상태·전송·완료·취소, 같은 환경 파일의 공개 범위·보존 코드 변경 |
| `files:delete` | 같은 환경의 완료 파일 삭제 |

관리자 화면의 **프로젝트 → API 키**에서 필요한 권한을 선택해 새 키를 발급한다. 기본 권한은 여전히 `integration:read`뿐이며 기존 키를 자동 확장하지 않는다. `X-Platform-Key`에 서버 API 키를 보낸다. 브라우저 코드·URL·문서·로그에 키를 넣지 않는다. 이용자별 파일 관리 권한은 아직 이 API가 판단하지 않으므로 호스트 서버가 자기 이용자의 접근 권한을 확인한 뒤 호출해야 한다.

진행 중 세션은 생성한 키에 귀속된다. 같은 환경의 다른 키도 해당 세션을 재개하거나 취소할 수 없다. 키가 폐기·만료되면 세션은 더 이상 재개할 수 없고 24시간 만료 후 정리된다. 완료 파일은 해당 환경의 권한 있는 서버 키가 관리한다. 다른 프로젝트·환경에서 ID를 알아도 관리·비공개 다운로드는 404로 거부한다.

각 보호 요청마다 파일 서비스가 프로젝트 서비스의 내부 API로 키·권한·환경 상태를 검사한다. 인증 결과를 캐시하지 않는다. 두 서비스는 별도 DB를 사용하며 `PLATFORM_FILES_SECRET`은 이 통신만 인증한다. 메일·이벤트·모니터링 비밀값과 구분하고 Nginx는 내부 API를 공개하지 않는다. 키 폐기·프로젝트 중지는 다음 요청부터 적용되며 이미 시작된 전송을 회수하지 않는다. 프로젝트 중지 또는 환경 미준비 시 공개 다운로드도 차단한다. 프로젝트 서비스가 응답하지 않으면 접근을 허용하지 않고 503을 반환한다.

## 업로드 계약

OpenAPI 원본은 [file-service/openapi.json](../services/file-service/src/main/resources/openapi.json)이며 `GET /api/v1/files/openapi`로도 조회한다(`files:read`). 관리자 개발자 포털의 통합 탐색은 후속 작업이다. 프로젝트 API의 기존 OpenAPI 명세와 별도로 제공한다.

| 순서 | 요청 | 결과 |
|---|---|---|
| 1 | `POST /api/v1/files/uploads` | 세션 ID, 확정 수신 위치, 만료 시각, 조각 상한 |
| 2 | `PATCH /api/v1/files/uploads/{id}` | 조각 저장 후 새 수신 위치 |
| 재개 | `GET /api/v1/files/uploads/{id}` | 서버가 확정한 위치부터 다시 전송 |
| 완료 | `POST /api/v1/files/uploads/{id}/complete` | 전체 크기·해시 확인 후 파일 정보 |
| 취소 | `DELETE /api/v1/files/uploads/{id}` | 미완료 세션 취소, 204 |

생성 본문 예:

```json
{
  "requestId": "73c47913-d64b-455c-ab97-8a44e4fa7da1",
  "originalName": "보고서.pdf",
  "size": 12345,
  "sha256": "원본 전체 바이트의 소문자 SHA-256 64자리",
  "visibility": "PUBLIC",
  "retentionCode": "default"
}
```

`requestId`는 호출자가 파일 항목마다 생성하는 UUID다. 같은 키·환경에서 같은 생성 본문을 재전송하면 같은 세션을 반환한다. 다른 본문으로 같은 ID를 재사용하면 409다. 나중에 공개 범위를 변경해도 최초 생성 요청의 재시도는 같은 세션을 가리킨다. 새 업로드는 새 요청 ID를 사용한다.

조각은 `Content-Type: application/octet-stream`, `Content-Length`, `Upload-Offset`, `X-Chunk-SHA256` 헤더와 원시 바이트를 보낸다. 조각 하나는 1~8,388,608바이트(8MiB), 위치는 서버의 `receivedBytes`와 같아야 한다. 한 파일은 순서대로 보내고, 여러 파일은 별도 세션으로 처리한다. 해시는 실제 조각 바이트의 소문자 SHA-256이다. 선언 길이·해시가 다르거나 전송이 끊기면 해당 조각을 확정하지 않는다. 조각 전체를 메모리에 적재하지 않고 64KiB 버퍼로 기록한다.

응답을 받지 못했다면 상태를 조회한다. 이미 확정된 위치에 같은 조각을 다시 보내면 409 `FILE_OFFSET_CONFLICT`이며 중복 저장하지 않는다. 일시정지는 다음 조각을 보내지 않는 것이다. 원본 파일은 호출자가 보관하고 재개 시 같은 내용을 제공해야 한다. 조각 해시와 완료 시 전체 해시를 모두 확인하므로 같은 이름만으로 파일을 판정하지 않는다.

[tus 1.0 명세](https://tus.io/protocols/resumable-upload)의 확정 위치·충돌·만료 방식을 검토했다. 이번 구현은 기존 JSON 오류/키 권한과 완료 검증 API에 맞춘 플랫폼 계약이며 **tus 호환 서버가 아니다**. 별도 tus 서버나 저장소 SDK는 도입하지 않았다.

DB 행 잠금으로 같은 세션의 동시 요청을 직렬화한다. 파일을 디스크에 동기화한 뒤 수신 위치를 커밋하며, 재시작/DB 롤백으로 뒤에 남은 바이트는 다음 전송 전 확정 위치로 잘라낸다. 완료 시 전체 파일을 스트리밍으로 해시 검사한 후 `READY`로 바꾸며 완료 재시도는 같은 파일 ID를 반환한다. 크기 0 파일은 조각 전송 없이 완료한다. 원본 이름은 경로로 사용하지 않는다.

세션 만료는 생성 후 24시간으로 고정되며 일시정지·재개로 연장하지 않는다. 만료 시각 이후 완료/전송은 거부한다. 완료 파일을 세션 취소로 지울 수 없으며 별도의 삭제 권한이 필요하다.

## 조회·다운로드·삭제

| 요청 | 용도 |
|---|---|
| `GET /api/v1/files?limit=20&offset=0` | 완료 파일만 조회, limit 1~100 |
| `GET /api/v1/files/{id}` | 파일 이름·크기·검증 해시·공개 범위·보존 코드·최근 이용 시각 |
| `GET /api/v1/files/{id}/download` | 원본 전체 다운로드 |
| `PUT /api/v1/files/{id}/visibility` | `{"visibility":"PRIVATE"}` 또는 `PUBLIC` |
| `DELETE /api/v1/files/{id}` | 즉시 논리 삭제, 204; 같은 환경에서 재시도 가능 |

기본은 `PUBLIC`으로 URL을 알면 콘텐츠와 해당 파일의 보기 정보를 받을 수 있다. 환경 전체 목록·관리는 공개하지 않는다. 비공개 파일은 같은 환경의 `files:read` 키 또는 파일별 보기 토큰이 필요하며 무인증 접근은 존재하지 않는 파일과 같은 404다.

다운로드 경로는 `application/octet-stream`·attachment, 검증된 보기 경로는 형식에 맞는 inline 응답이다. HTML/SVG·미지원 원본은 attachment를 유지한다. `nosniff`·`no-store`와 용도별 CSP를 적용하고 공개→비공개 전환 후 플랫폼 캐시 우회를 막는다. 단일 `Range: bytes=...` 요청은 206과 Content-Range를 반환하며 잘못된/다중 범위는 416이다. If-Range 검증자를 제공하지 않아 해당 조건부 요청은 전체 200으로 반환한다. HEAD는 인증/헤더 확인만 하며 이용 시각을 늘리지 않는다.

최초 이용 시각은 완료 시각이다. 원본·썸네일·미리보기의 GET/206 전송이 오류 없이 끝나면 `lastUsedAt`을 갱신하고 삭제 유예를 해제한다. 목록·정보·URL 발급·뷰어 HTML 자체·내부 변환·실패·HEAD는 갱신하지 않는다. 실제 콘텐츠를 요청한 봇도 GET 기준에 포함한다. 네트워크 전송 성공은 이용자가 파일을 실제 열었다는 보장이 아니다.

파일 삭제는 DB 상태와 감사 기록을 같은 트랜잭션에 저장해 즉시 신규 접근을 차단한다. 60초 주기 정리기가 취소·만료·삭제 파일을 최대 100개씩 원본·썸네일 함께 물리 삭제하며 실패는 다음 회차에 재시도한다. 재시작 후에도 대상 상태를 유지한다. 디스크 정리 완료 전에는 해당 파일의 예약 용량을 반환하지 않는다. 이미 시작된 응답과 이용자가 저장한 사본은 회수하지 않는다.

## 보기 URL과 지원표

서버는 `POST /api/v1/files/{id}/view-ticket`에 `files:read` 키를, 관리자는 `POST /api/v1/files/admin/environments/{environmentId}/{id}/views`에 JWT를 보낸다. 공개는 고정 URL, 비공개는 최대 5분(관리자 JWT 만료 이내)의 재사용 가능한 파일별 토큰 URL이다. 영상의 여러 Range 요청 때문에 일회용 다운로드 링크와 구분한다. 파일당 최근 20개까지 유지한다. DB에는 해시만 저장하며 공개 범위 변경·삭제·환경 접근 차단이 모든 보기 경로에 적용된다.

`GET /api/v1/files/{id}/views`는 공개 또는 보호 권한을 확인한 뒤 상태·URL을 반환한다. `/view`는 기본 HTML 뷰어, `/content/{variant}`의 variant는 `original`·`preview`·`thumbnail`·`download`다. 썸네일/미리보기가 없으면 해당 URL은 null이다. 임시 URL은 파일 접근 권한을 포함하므로 로그·공개 문서에 기록하지 않는다. 외부 NPM/CDN도 토큰이 들어간 쿼리 로그를 보관하지 않도록 운영 설정을 확인해야 한다.

| 입력 | 현재 보기 | 처리 한도·대체 동작 |
|---|---|---|
| PNG·JPEG·GIF·WebP | 원본 이미지·480×320 이내 JPEG 썸네일 | 32MB, 4천만 픽셀 이하, 각 변 10,000 이하. 애니메이션 썸네일은 첫 프레임 |
| MP4·WebM | 원본 영상 재생·대표 JPEG | 1GB, 850만 픽셀 이하, H.264/VP8/VP9/AV1 영상. 실제 재생은 브라우저·오디오 코덱에 따라 다름 |
| MP3·WAV | 원본 오디오 재생 | 1GB 이하, 브라우저 지원에 따름 |
| PDF | 브라우저 PDF 보기 | 100MB 이하. 암호화·손상 문서는 브라우저 오류/암호 안내 또는 다운로드 |
| UTF-8 TXT·MD | 텍스트·안전한 Markdown HTML | 256KiB 이하, 잘못된 UTF-8/NUL 거부. MD의 HTML은 이스케이프, 위험 URL 제거, 외부 이미지·스크립트 차단 |
| HTML·SVG·Office·HWP·기타 / 한도 초과 | 파일 정보·다운로드 | 원본은 보존, 미리보기 미지원 표시 |

형식은 확장자만 믿지 않고 제한된 FFprobe 결과와 이미지 코덱을 함께 확인한다. PDF는 헤더 확인 후 브라우저가 파싱한다. 텍스트는 UTF-8 검증한다. [CommonMark 렌더러의 HTML·URL 보호 옵션](https://github.com/commonmark/commonmark-java)과 CSP sandbox를 함께 사용한다. 기본 뷰어는 스크립트 없이 서버가 만든 HTML이며 임의 업로드 HTML을 실행하지 않는다.

`file_views` 영속 큐의 QUEUED→PROCESSING→READY/UNSUPPORTED/FAILED를 사용한다. 3초 간격으로 한 파일씩 처리하고 완료된 기존 파일도 발견한다. 2분 이상 중단된 PROCESSING은 최대 3회까지 재점유한 뒤 실패하며 관리자가 재시도할 수 있다. FFprobe 15초·FFmpeg 30초, 각각 가상 메모리 384MiB·출력 파일 2MiB, 한 스레드와 로컬 파일/제한된 demuxer만 허용한다. 요청 처리와 변환을 분리하며 명령 인자는 셸 코드로 보간하지 않는다. [FFmpeg 옵션](https://www.ffmpeg.org/ffmpeg.html)의 `max_alloc`은 단일 할당 제한이라 프로세스 제한도 함께 둔다. 공통 Job 화면 통합은 후속 작업이다.

## 보존 정책과 자동 정리

**보존 정책 → 보존 코드 / 자동 정리 / 변경 이력**에서 관리한다. `default`는 초기 1년, `tmp`는 1일, `영구`는 자동 삭제 없음이다. 사용자 코드는 일·개월·년으로 만들며 환경당 총 100개다. 고정 코드 삭제/중지는 불가하고 영구 기간은 바꾸지 못한다. 사용자 코드 비활성화는 새 선택만 막으며 기존 파일의 현재 기간은 유지한다. 파일 상세에서 개별 코드를 바꿀 수 있다.

UTC 달력 기준이며 월말·윤년은 유효한 마지막 날로 맞춘다. 코드 기간 변경은 기존 파일에도 즉시 적용된다. 변경 전에 영향 파일·새 기준 기간 초과 파일 수를 확인하고 revision/대상 수가 달라졌으면 409로 재확인을 요구한다. 설정과 변경 전후·처리자·요청 ID 감사를 같은 트랜잭션에 기록한다.

자동 정리는 환경별 **기본 꺼짐**, 삭제 유예는 기본 **7일(1~30일)**이다. 60초 주기로 켜진 환경 중 최근 검사 순서로 20개, 환경당 최대 100개를 확인한다. 기간 초과를 발견하면 유예 시작 시각을 기록하며 다음 회차에 최신 정책/사용 시각/전송 여부를 확인한 뒤 논리 삭제한다. 정책·정리 설정·파일 코드 변경은 해당 파일의 유예를 초기화한다. 콘텐츠 이용이나 영구 변경으로 대상에서 빠지며 자동 정리를 끄면 삭제를 중단한다. 유예는 삭제 전 대기이므로 이미 삭제된 파일은 복원하지 않는다. 백업 보존은 운영자의 별도 백업 정책이다.

진행 중 콘텐츠 전송은 2분 DB lease와 20초 갱신, 로컬 90초 만료 검사를 사용해 자동 정리에서 제외한다. 응답 실패는 이용 시각을 갱신하지 않는다. 스케줄러 풀을 4개로 분리해 변환이 전송 갱신을 막지 않도록 한다. 현재는 단일 파일 서비스 실행을 전제로 한다.

## 저장소와 운영

- 파일 DB: `platform_file`. 메타데이터·세션·보존 코드 참조·감사 기록을 저장한다.
- 원본: Compose `file-data` 영속 볼륨의 `/app/storage`. 비특권 앱 사용자 소유이며 UUID 기반 이름만 사용한다. Nginx에서 이 경로를 직접 공개하지 않는다.
- 처음 사용하는 환경에 `default`(달력 1년), `tmp`(1일), `영구` 정책 행을 만든다. 미등록/사용 중지 코드는 신규 선택 시 거부한다. V3는 보존 관리·전송 lease, V4는 보기 작업·권한 토큰을 추가한다.
- 파일 서비스 메모리 기본값은 `FILE_MEMORY=1g`, JVM은 전용 `FILE_JAVA_TOOL_OPTIONS`의 MaxRAMPercentage=35다. FFmpeg의 프로세스 공간을 남긴다. 기존 `.env`의 512m 값은 자동 upgrade로 바뀌지 않으므로 배포 시 1g로 조정한다. 새 외부 포트/상시 프로세스는 없고 변환할 때만 제한된 FFmpeg 프로세스를 실행한다.
- 기본 환경 예약 한도: `FILE_ENVIRONMENT_QUOTA=50000000000`(50GB), 미완료 세션 수: `FILE_PENDING_LIMIT=20`. 파일 크기를 미리 예약해 완료 파일과 진행 중 업로드를 함께 계산한다. 단일 공유 디스크에서 모든 환경의 남은 예약 바이트도 확인하고 실제 여유 256MiB를 남긴다. 전체 DB 메타데이터 수/요청 빈도 제한은 별도 운영 보완 사항이다.
- 단일 파일 서비스와 로컬 영속 볼륨으로 시작한다. 인스턴스를 여러 호스트에 복제하기 전 공유 저장소·분산 파일 잠금/배치 전략을 별도로 검토한다. DB만 복구하거나 볼륨만 복구하면 일치하지 않을 수 있어 둘을 함께 백업한다. 전원 장애·디스크 장애 복구는 별도 검수 대상이다.
- Nginx 파일 경로만 요청 상한 8MiB, 본문 대기 30초, 응답 대기 300초다. 외부 NPM도 이 크기/시간을 허용해야 한다. 다른 API의 기존 1MiB 상한은 유지한다. HTTP 진입은 기존 30140이며 새 외부 포트를 열지 않는다.

설정 추가는 `python scripts/init-env.py --upgrade`로 한다. 기존 `.env` 값을 덮어쓰지 않는다. 파일/프로젝트/Nginx 이미지를 빌드한 뒤 해당 서비스만 재생성한다. 기존 볼륨에 사용자 파일을 임의로 복사하거나 이전 파일 서비스를 이전하지 않는다.

## 검증과 재개

격리 DB 검증은 운영 Compose와 결합하지 않는다.

```powershell
docker compose -p platform-job-checks -f compose.jobs-test.yml up --abort-on-container-exit --exit-code-from check
docker compose -p platform-job-checks -f compose.jobs-test.yml down
```

개발 서버 실제 검사는 전용 프로젝트 2개와 DEV/PROD 환경을 만들며 일반 회원·기존 프로젝트를 변경하지 않는다. 검사 후 키 폐기·파일 삭제/취소·프로젝트 중지·검사 관리자 세션 로그아웃을 수행하고 감사 이력은 남긴다. 중간 상태 파일에는 단기 검사 키가 있어 Git 제외 `output/playwright/file-check.json`에만 두며 정상 종료 후 삭제한다.

```powershell
docker compose -f compose.yml -f compose.dev.yml --profile test run --rm --no-deps file-check --phase start
docker compose -f compose.yml -f compose.dev.yml restart file-service
# file-service가 healthy가 된 뒤
docker compose -f compose.yml -f compose.dev.yml --profile test run --rm --no-deps file-check --phase finish
```

중간 종료 시 `--phase cleanup`을 사용한다. 검사 키가 만료되면 관리자에서 해당 검사 프로젝트·키를 확인해 정리하고, 미완료 원본은 세션 만료 정리기가 처리한다. 검사 스크립트는 비밀값을 출력하지 않는다. 기본 실제 전송 샘플은 약 7MB이며 5GB 선언 상한/초과 거부와 실제 5GB 전체 전송 성능은 다른 검증이다. 실제 실행 결과와 미검증 범위는 [STATUS](STATUS.md)를 따른다.

후속 단위는 비밀번호 공유·OG·중복 안내·이용자 위임 업로드와 공통 Job 관리 연결이다. 모니터링 추가 확장은 사용자 요청 시 재개한다.

## 영상 스트리밍

업로드 완료 후 `file_videos` DB 큐가 기존/새 MP4·M4V·MOV·MKV·WebM을 발견한다. 입력은 최대 파일 한도 5GB 안에서 **60분 이하·가로세로 각각 4096px 이하·850만 화소 이하**, 정사각 픽셀, H.264/HEVC/VP8/VP9/AV1/MPEG-4/MJPEG 영상이다. 컨테이너 실제 형식을 검사하고 파일 경로 이외의 입력 프로토콜은 차단한다. 일반 원본 미리보기의 1GB·코덱 한도와 별도다. 지원하지 않는 입력도 원본은 보존한다.

- 출력은 H.264 High/yuv420p, 30fps, 오디오가 있으면 AAC 128kbps·48kHz·스테레오다. 무음 영상에 오디오를 임의로 만들지 않는다. 약 6초 MPEG-TS 조각과 VOD 재생 목록을 생성한다. 화질별 경계에 키프레임을 맞춘다.
- 360/720/1080 중 원본 **짧은 변 이하**만 만들며 세로·회전 메타데이터를 반영한다. 360보다 작은 입력은 원본 이하의 짝수 크기 한 가지로 제공한다. 비율을 유지하고 확대하지 않는다. 예: 720×1280 → 360×640, 720×1280.
- 영상 비트레이트 목표는 0.8/2.5/4.5Mbps이며 최대 비트레이트는 1.2배다. 입력 크기만으로 출력 공간을 예측하지 않고 길이·화질 수·최대 비트레이트로 넉넉하게 예약한다. 예약과 변환본 실제 용량은 환경 50GB 기본 한도에 포함하며 업로드 예약과 같은 잠금으로 검사한다. 변환 중 디스크와 출력 총량을 계속 확인한다.
- 썸네일 작업과 같은 프로세스 제한 안에서 변환을 한 번에 하나씩 실행한다. DB 세션 잠금으로 다른 서비스 인스턴스의 동시 변환도 막는다. FFmpeg 단일 인코딩 스레드·가상 메모리 512MiB·출력 파일당 16MiB, 화질당 제한 시간은 `max(120초, 영상 길이×8)`의 최대 4시간이다. HLS 준비 전에는 일부 결과를 공개하지 않는다.
- 상태는 QUEUED/PROCESSING/READY/UNSUPPORTED/FAILED다. 진행률은 완료한 화질 수 기준이며 예상 시간으로 만들지 않는다. 2분 이상 heartbeat가 끊긴 작업은 부분 결과·예약을 정리하고 최대 3회 재시작한다. 일반 변환 실패는 관리자가 원인을 확인하고 **영상 변환 다시 시도**로 요청한다. 원본·변환본은 같은 삭제 정책을 따른다. 명시적 삭제는 즉시 접근을 막고 워커가 중단한 뒤 파일 정리기가 파생 디렉터리까지 제거한다.

| 경로 | 용도 |
| --- | --- |
| `GET /api/v1/files/{id}/hls/{asset}` | `master.m3u8`, 화질별 m3u8, TS 조각. 매 요청 현재 파일/프로젝트 권한 검사 |
| `POST /api/v1/files/admin/environments/{environmentId}/{id}/video/retry` | 관리자 JWT로 실패 변환 재요청 |
| `GET /api/v1/files/{id}/view` | 영상은 동일 출처 `/file-viewer.html`로 이동. 별도 관리자 로그인 없이 파일 링크 권한으로 재생 |

보기 응답의 `video`에는 상태·완료 비율·길이·생성 화질·오류 코드, `streamUrl`에는 준비된 HLS 주소를 제공한다. 비공개 원본·썸네일·보기 진입 URL은 기존 **최대 5분**, 스트리밍 조각 전용은 `streamExpiresAt`까지 **최대 2시간**이다. 재생 권한은 원본 보기 권한의 만료를 연장하지 않는다. 재생 목록 안의 모든 하위 재생 목록·조각 URL에도 토큰을 넣으며, 공개 전환/비공개 재전환·삭제·프로젝트 중지를 매 요청 검사한다. 파일당 최근 20개 보기 세션 제한은 그대로다. 토큰·질의 문자열은 로그에 남기지 않는다. 세그먼트의 성공한 GET/206만 최근 이용을 갱신하며 재생 목록·HEAD는 제외한다.

관리자·전용 뷰어는 [hls.js](https://github.com/video-dev/hls.js) 1.7.3을 필요할 때만 불러온다. MSE 재생을 우선하고 지원하지 않으면 브라우저 기본 HLS를 사용한다. 영상 안쪽 오른쪽 위 화질 설정에서 자동 또는 생성 화질을 선택하고 재생 막대로 이동한다. 옆 전체 화면 버튼은 영상과 화질 메뉴를 함께 확대하며 Fullscreen API 미지원 시 페이지를 채우는 표시로 대체한다. 원본 다운로드를 함께 제공하며 브라우저가 스트리밍을 지원하지 않으면 안내한다. 외부 CDN 스크립트는 사용하지 않는다. 전용 뷰어는 관리자 인증 코드를 불러오지 않는다. 외부 서비스는 서버에서 보기 링크를 발급하고 반환된 HLS URL을 자기 플레이어에 연결할 수 있다. 현재 교차 출처 브라우저 요청용 CORS·임베드 허용 정책은 제공하지 않아, 다른 출처의 직접 재생은 별도 연동 정책이 필요하다.

HLS 옵션은 [FFmpeg Formats](https://ffmpeg.org/ffmpeg-formats.html)를 따른다. 4K 출력·라이브·DRM·GPU 가속·Office/HWP 변환·모든 코덱 지원은 이번 구현에 포함하지 않는다. 실제 검증한 브라우저와 미검증 범위는 STATUS를 따른다.
