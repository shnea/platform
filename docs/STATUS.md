# 작업 상태와 다음 작업

## 현재 단계

요구사항 합의와 저장소 준비 단계. 애플리케이션 코드·Compose·Docker 이미지·실행 서비스는 아직 없다.

## 이번에 정리한 내용

- 루트 `REQUIREMENTS.md`를 핵심 요약으로 추가하고 상세 문서를 `docs/REQUIREMENTS.md`로 통일했다. 읽기 순서와 요구사항 동시 갱신 규칙을 연결했다.
- 11개 항목의 요구사항과 기능별 검수 시나리오 작성.
- Keycloak, MSA, Nginx 30140·추가 외부 포트 순차 배정 확정.
- 에디터·뷰어 첫 출시 및 React·Vue 패키지/일반 JS·CSS 배포 확정.
- Markdown 문서 내용 붙여넣기의 블록 변환·올바른 렌더링과 뷰어 일치를 필수 요구·검수 조건으로 추가.
- 기본 공개 파일, 비공개·비밀번호 공유, 최대 5GB·멀티·분할·일시정지·재개 업로드 반영.
- 고정 보존 코드 3개와 사용자 등록 코드, 기간 변경의 기존 파일 적용 반영.
- NCP 이메일·SMS, 알림 6개 채널, 독립 사용·연동 검증·운영 현황·웹훅 반영.
- 작업 단위별 한글 커밋·푸시와 재개 절차를 `AGENTS.md`에 기록.
- HTTPS 원격 저장소의 읽기 접근과 비어 있는 상태를 확인하고 로컬 `main`과 `origin`을 준비.

## 구현 순서

아래 순서는 작업 단위이며 모두 합의한 첫 출시 범위에 포함된다.

1. **다음 작업: MSA 실행 기반.** 서비스 경계·지원 버전·이미지 목록을 정하고 Nginx/Keycloak/DB/관리·파일·알림 서비스의 개발용 Compose와 비밀값 없는 환경변수 예시를 구성한다. 환경변수로 자원을 조정하고 서비스 상태·30140 라우팅을 검증한다.
2. **프로젝트·인증·개발 모드.** 프로젝트별 계정·가입 방식, 서비스 자격증명·권한, Keycloak 관리 연동, 가짜 인증/발송의 운영 격리를 구현한다.
3. **파일 서비스.** 5GB·멀티·드래그·분할·재개 업로드, URL·공개/보호 공유, 미리보기·뷰어, 보존 코드와 실제 삭제 처리를 구현한다.
4. **알림·웹훅.** 6개 채널, NCP 연동, 앱 내 알림, 모의 수신함, 재시도·중복 방지, 서명 웹훅을 구현한다.
5. **에디터·뷰어·통합 관리.** 공통 문서 형식과 UI, Markdown 붙여넣기 렌더링, React·Vue·일반 JS 배포, 자체 업로드 교체, 운영 화면과 연동 예제를 완성한다. 관리자 화면은 각 서비스 구현과 함께 필요한 부분부터 만든다.
6. **첫 출시 검증.** 전체 완료 조건, 실제 외부 연동, macOS·Windows·Linux, 부하·백업 복원·배포 절차를 검증한다.

## 확정 사항을 다시 묻지 않을 것

- Keycloak 사용, MSA, 에디터 첫 출시·호스트 본문 저장·다중 프레임워크 배포.
- 파일 기본 공개와 비공개/비밀번호 공유, 최대 5GB·분할·재개.
- 고정 코드 `default`·`tmp`·`영구`만 제공, 나머지는 코드 등록 시 기간 지정. 코드 변경은 기존 파일에도 적용.
- 이메일·SMS는 NCP. 알림 6개 채널과 웹훅 모두 포함.
- 외부 진입 Nginx 30140, DB 외부 접근 시 30141, 추가 외부 포트 순차 증가.
- Git HTTPS 주소와 작업 단위별 한글 커밋·푸시.

## 아직 필요한 상세 결정·정보

- Java/Spring Boot·PostgreSQL·React/Vite·에디터 라이브러리의 지원 버전과 실제 이미지 아키텍처 확인. Keycloak·MSA 자체는 이미 확정이다.
- 프로젝트 내 개발·운영 회원 분리의 상세 모델, 가입·복구 방식 목록, 소셜 앱 등록 현황과 카카오·네이버 어댑터.
- NCP 발신 설정·연동 계정, 카카오 메시지 종류·제공 업체, Telegram 봇, 웹 푸시 지원 범위. 실제 키는 문서에 넣지 않는다.
- 파일 미리보기 형식 목록, 공개 OG 정보, 보존 기간 계산·최근 이용 집계·삭제 유예, 업로드 세션 보관 기간.
- 패키지 배포 위치·이름과 프레임워크 지원 버전, 운영 도메인/TLS·백업 저장소·측정할 부하 조건.
- API 필드명·조각 크기 등 통상적인 구현 세부사항은 합리적인 기본값과 근거로 진행하고, 사용자에게 모든 수치를 결정하도록 요구하지 않는다.

## 검증 상태

- 문서의 Keycloak 미정·단일 백엔드 제안·에디터 출시 미정 등 오래된 표현을 최신 결정과 대조해 정리했다.
- Git 원격 읽기 확인: 처음 HTTPS 연결이 시간 초과였으나 재시도는 성공했고 기존 refs는 없었다.
- 제품 테스트: 코드와 실행 환경이 아직 없어 미실행. 기능 동작·부하·OS 호환·실제 발송 검증 결과는 아직 없다.
- 문서 4개의 로컬 링크와 요구사항 1~11절 존재, 개인 키 표식 검사를 실행해 통과했다.
- 첫 커밋 대상 6개 파일을 확인했고 `git diff --cached --check`를 통과했다. 개인 IDE 설정은 제외했다. 푸시 결과는 아래 Git 재개 명령으로 실제 확인한다.

## 다음 세션의 확인 명령

```bash
git status --short --branch
git log -5 --oneline
git remote -v
git fetch origin
git status --short --branch
```

`ahead`이면 미푸시 커밋을 확인하고 검증 후 푸시한다. `behind`나 분기가 있으면 사용자 변경을 보존하며 원격 이력을 먼저 반영한다. 현재 이 문서에 기록할 실행 중 애플리케이션 프로세스는 없다.
