# 관리자 OTP 선택과 계정 복구

관리자는 **내 계정 → 계정 보안 → OTP 사용**에서 2단계 인증을 선택한다. 사용하지 않는 계정은 비밀번호로 로그인한다. 사용 중인 계정은 비밀번호 뒤에 인증 앱의 일회용 코드 또는 미리 보관한 복구 코드가 필요하다. 기존에 등록한 인증 앱·복구 코드는 그대로 유지한다. 개발·운영 관리자에 같은 브라우저 정책을 적용하며 프로젝트 회원·master 계정은 이 정책의 대상이 아니다.

## 등록과 평소 사용

1. 플랫폼에 로그인하고 오른쪽 위 **내 계정**을 누른다. **계정 보안 → OTP 사용**에 체크하면 인증 앱 등록 화면이 열린다. 인증 앱 등록을 취소하면 사용 상태로 바뀌지 않는다.
2. 처음 발급된 관리자는 `admin`, 초기 비밀번호는 `.env.dev` / `.env.prod`의 `PLATFORM_ADMIN_PASSWORD`다. 한 번 변경했다면 변경한 비밀번호를 사용한다. 초기화 재실행은 기존 비밀번호를 되돌리지 않는다.
3. 본인 인증 앱에서 QR 코드를 스캔하고 표시된 일회용 코드를 입력한다. 구분할 수 있는 기기 이름을 붙인다.
4. 복구 코드 12개를 다운로드하거나 인쇄해 인증 기기와 별도로 보관한다. 보관 확인에 체크한 뒤 설정을 완료한다. QR·비밀키·복구 코드를 관리자에게 보내지 않는다.
5. 다음 로그인에서는 비밀번호 뒤에 인증 코드를 입력한다. 인증 화면과 계정 관리 안내는 한국어로 표시한다.

앱을 분실했지만 복구 코드가 있으면 **다른 인증 방법 → 복구 코드**를 선택하고 화면에 표시된 번호의 코드를 입력한다. 각 코드는 한 번만 사용할 수 있다. 로그인 후 **계정 보안 → 로그인 방법**에서 새 인증 앱을 먼저 등록·확인한 다음 분실한 앱을 제거하고 새 복구 코드를 발급한다. 새 코드 발급으로 이전 코드 목록은 무효가 된다.

## OTP 사용 해제

1. **내 계정 → OTP 사용**의 체크를 누른다.
2. 등록된 수단이 여러 개면 제거 목록이 나온다. 복구 코드를 먼저 제거하고 인증 앱을 마지막에 제거하면 남은 인증 수단으로 본인 확인을 이어갈 수 있다.
3. 각 항목마다 비밀번호·현재 2단계 인증으로 본인을 다시 확인하고 제거를 확정한다. 취소하면 해당 수단은 유지된다.
4. 인증 앱과 복구 코드가 모두 제거된 뒤 체크가 꺼진다. 다음 로그인부터 비밀번호만 사용한다. 다시 사용하려면 새 인증 앱을 등록한다.

체크 상태는 서버의 실제 등록 상태를 표시한다. 브라우저에 별도 사용 여부를 저장하거나 로그인 화면에서 인증을 건너뛰는 방식이 아니다. 계정 보안 조회에 실패하면 체크를 비활성화하며 **계정 관리 열기**로 기존 계정 관리 화면에 접근할 수 있다. 비밀번호 변경·기기별 관리는 이 화면의 **계정 보안 → 로그인 방법**에서 수행한다.

## 인증 앱과 복구 코드를 모두 잃은 경우

이 절차는 서버와 Keycloak master 자격증명에 접근할 수 있는 운영자만 수행한다. 이메일 수신만으로 관리자 MFA를 해제하지 않는다. 운영자는 요청자의 신원을 별도 경로로 확인하고 복구 사유·대상 계정·실행 결과를 운영 기록에 남긴다. 같은 계정의 복구 명령은 동시에 실행하지 않는다.

아래 PowerShell 예시는 저장소 루트에서 실행한다. `.recovery`는 Git에서 제외하지만 Windows 폴더 권한도 해당 운영자만 접근할 수 있도록 제한해야 한다. 명령의 `admin`은 정확한 대상 아이디로 바꾸고, 사유에는 비밀번호나 코드를 적지 않는다.

```powershell
New-Item -ItemType Directory -Force .recovery
docker compose -f compose.yml --profile setup run --rm --no-deps -e PLATFORM_MODE=prod --volume "${PWD}/.recovery:/recovery" --entrypoint python identity-setup /tools/admin_security.py recover --username admin --reason "본인 확인 후 인증 기기와 복구 코드 분실 복구" --password-file /recovery/admin-password
```

Linux에서는 전용 디렉터리를 `mkdir -m 700 .recovery`로 만든다. 같은 명령에서 볼륨을 `"$PWD/.recovery:/recovery"`로 지정하고 `--user "$(id -u):$(id -g)"`를 추가하면 해당 운영자 권한으로 파일을 생성한다. 도구는 임시 비밀번호 파일을 0600·새 파일로만 생성하며, 기존 파일이 있으면 계정을 변경하기 전에 중단한다. 개발 이미지로 검수할 때는 `-f compose.dev.yml`을 추가한다.

도구는 대상의 관리자 역할과 플랫폼이 관리하는 MFA 흐름을 확인하고 다음 순서로 실행한다.

1. 로그인 차단 → 온라인·오프라인 세션 종료.
2. 기존 인증 앱·복구 코드·보안 키 폐기 → 무작위 임시 비밀번호 설정.
3. 기존 필수 동작을 보존하며 비밀번호 변경·인증 앱 등록·복구 코드 발급을 요구.
4. 세션과 로그인 실패 잠금을 정리한 뒤 로그인 허용.

임시 비밀번호는 파일에만 쓰며 콘솔에 출력하지 않는다. 운영자는 본인에게 안전한 경로로 전달하고, 본인은 다음 로그인에서 새 비밀번호·인증 앱·복구 코드를 등록한다. 계정 정보와 역할은 보존한다. 완료 확인 후 해당 임시 파일을 삭제한다. `.env.dev` / `.env.prod`의 초기 비밀번호를 수정하거나 공유할 필요는 없다.

중간 실패 시 계정을 다시 활성화하지 않는다. 상태를 확인하고 원인을 해결한 뒤 **다른 새 비밀번호 파일명**으로 같은 명령을 다시 실행한다. 마지막 로그인 허용 요청의 응답만 유실되면 실제 활성 상태는 별도 조회해야 하며, 이 시점에도 비밀번호 변경·MFA 재등록 요구는 이미 저장되어 있다. 출력의 `completed=false`를 성공으로 처리하지 않는다.

Keycloak 관리자 이벤트에는 운영자·시간·대상·비밀번호 변경·인증 수단 폐기 등의 결과를 기록한다. 요청 본문 기록은 끄므로 비밀번호와 인증 키가 이벤트에 저장되지 않는다. 기존 사용자 이벤트 설정은 보존한다. 복구 사유와 묶음 작업 결과는 도구의 JSON 출력에 있으며 이를 운영 기록에 함께 보관한다. 플랫폼 프로젝트 감사 화면에는 이 운영자 이벤트가 표시되지 않는다.

이미 발급된 접근 토큰을 서명만으로 검증하는 API는 만료 전 즉시 차단을 보장하지 않는다. 관리자 토큰 수명은 현재 5분이다. 계정 데이터 삭제나 realm 재생성으로 복구하지 않는다. master 자격증명까지 분실한 경우의 서버 부트스트랩 복구·백업 복원은 별도 절차다.

## 배포와 검증

GitHub 자동 배포가 새 tools·관리자 웹 이미지를 가져오고 기존 `identity-setup`으로 정책을 반영한다. 독립된 `platform-admin-mfa-v3-optional` 흐름은 등록된 인증 앱 또는 복구 코드가 있을 때만 2단계 인증을 요구하며, 운영 비밀번호 단독 직접 토큰 발급은 계속 차단한다. 기존 비밀번호·OTP·복구 코드는 보존한다. 최초 전환 시 기존 세션을 종료하므로 다시 로그인해야 한다. 미등록 계정에 남아 있던 이전 강제 등록 요구만 제거하고, 운영자 복구 중인 비밀번호 변경·MFA 재등록 요구는 보존한다. 재실행은 계정 선택·인증 수단·세션을 초기화하지 않는다. 별도 인증 흐름이나 같은 이름의 다른 흐름이 있으면 검토할 수 있도록 중단한다.

```sh
python scripts/check-admin-security.py
./scripts/dev.ps1 --profile setup run --rm --no-deps -e PLATFORM_MODE=prod identity-setup
./scripts/dev.ps1 --profile test run --rm smoke
```

오프라인 검사는 조건부 인증 흐름·이전 정책 전환·반복 실행·직접 토큰 발급 차단·해제 재인증 설정을 확인한다. 복구 검사에서는 세션 종료·비밀번호 설정 실패 뒤 로그인 차단 유지, 비밀번호 비출력, 기존 출력 파일·필수 동작·이벤트 설정 보존을 확인한다. 실제 브라우저 검증과 배포 결과는 [작업 상태](STATUS.md)에 기록한다. 본인 관리자 계정의 인증 앱과 복구 코드는 본인이 등록·보관한다.

기반 동작은 [Keycloak 관리자 안내](https://www.keycloak.org/docs/latest/server_admin/)의 OTP·Recovery Codes·Application Initiated Actions를 따른다. 등록과 제거에는 `CONFIGURE_TOTP`, `delete_credential`을 사용하며 인증 키는 플랫폼 화면·API로 전달하지 않는다. 구현은 Keycloak 26.7.4에 맞췄으므로 버전 변경 시 이 흐름과 복구를 다시 검증한다.
